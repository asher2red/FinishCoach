# 검증 결과와 수동 체크리스트

## 자동 검증

2026-10-17 작업 환경에서 수행했다. TypeScript 및 ESLint는 오류·경고 없이 통과했고, Vitest 20개와 Chrome E2E 2개가 통과했다. New York 시간대에서도 20개가 통과했다. 웹 정적 빌드와 Android/iOS Hermes 번들 생성도 성공했다.

| 검증                 | 범위                                                                                                                                                             |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| TypeScript strict    | 앱·도메인·서비스·테스트 타입                                                                                                                                     |
| ESLint               | Expo flat 설정, React hook 규칙                                                                                                                                  |
| Vitest               | 루틴 생성/수정/중지, 매일/요일/주간 목표/일회성, 기간/중복/장기 공백, 완료/취소, 통계, 시간대 변경/DST, 현지 시각 입력, 프로젝트, SQLite, IndexedDB, 알림 어댑터 |
| New York TZ          | DST 지역에서 도메인·저장소 테스트 재실행                                                                                                                         |
| Playwright Chrome    | 실제 IndexedDB 저장과 reload, 완료/취소, 기록 수정, 실제 통계, 주간 목표, 프로젝트/마일스톤 완료, 빈 화면, 다크 모드, 유효성 검사                                |
| Expo export          | 웹 정적 경로 및 Android/iOS Hermes 번들                                                                                                                          |
| Expo install --check | SDK 58 의존성 호환성                                                                                                                                             |
| Expo doctor          | 19/20 검사 완료. 원격 설정 스키마 검사는 exp.host 연결 시간초과                                                                                                  |

SQLite 테스트는 Node 내장 SQLite의 실제 SQL 및 파일 재열기를 사용한다. Expo 네이티브 모듈 호출은 어댑터로 대체한다. Notification 테스트도 OS 대신 mock을 사용하므로 실기기 전달을 증명하지 않는다. Android는 이후 EAS에서 내부 배포용 APK 컴파일·서명을 완료했다(빌드 ID `04171dbc-591a-4901-9c6a-0a1c3bbe7288`). 실기기 설치·구동은 아직 검증하지 않았고, iOS 바이너리 컴파일 및 스토어 제출도 수행하지 않았다. 이 환경에는 Xcode simctl과 adb가 없다.

`npm audit fix`를 실행했다. 취약점 27건(높음 19, 보통 8)은 남아 있다. 강제 수정은 호환되지 않는 Expo 44 다운그레이드여서 적용하지 않았다. 네트워크가 가능한 환경에서 doctor와 audit을 재확인해야 한다.

## 공통 기능 수동 검사

- [ ] 빈 설치: 예정·기록·프로젝트가 빈 안내를 표시하고 임의 데이터가 없는지 확인.
- [ ] 독서/운동/취침/사용자 활동으로 루틴 생성, 직접 만든 활동이 다음 선택 목록에 있는지 확인.
- [ ] 매일/요일/주 N회/일회성, 미래 시작일, 종료일, 윤년, 월말 검증.
- [ ] 오늘 완료를 연속 탭해 중복 로그가 없는지 확인. 완료 취소 후 재완료.
- [ ] 실제 완료 날짜/시각·소요 시간·메모 수정 후 주/월 통계 일치 확인.
- [ ] 완료 취소 → 루틴 시각 수정 → 저장 성공 및 취소 로그 보존 확인.
- [ ] 루틴 비활성/보관 후 미래 미완료 일정 제거와 과거 로그 보존, 복원 확인.
- [ ] 앱 강제 종료 후 재실행해 루틴/기록/프로젝트/마일스톤 영속성 확인.
- [ ] 프로젝트 수정, 마일스톤 이름/순서/완료/삭제, 상태 보류/재개/완료/취소 확인.
- [ ] 큰 글자 크기, VoiceOver/TalkBack, 긴 한글 제목, 작은 화면, 가로 화면, 다크 모드 확인.
- [ ] 저장 공간 부족 등 DB 실패 시 오류가 보이고 잘못된 성공 상태로 넘어가지 않는지 확인.

## Android 실제 기기

- [ ] SDK 58 자체 개발 빌드 설치. Android 13+ 권한 요청 전에 알림 채널 생성 확인.
- [ ] 알림 거부 후에도 저장/완료/기록 조회 정상 동작.
- [ ] 몇 분 뒤 알림, 시각 변경 후 이전 알림 취소, 비활성/보관 후 취소.
- [ ] 정확한 알람 권한이 없는 Android 14+에서 지연 안내와 best-effort 전달 확인.
- [ ] 잠금/절전/배터리 최적화/집중 모드/OEM별 백그라운드 전달 차이 확인.
- [ ] 재부팅·앱 업데이트 후 기존 예약 복구, 앱 재개 후 보충 확인.
- [ ] 시간대·날짜 변경 후 현지 일정 및 알림 재계산 확인.
- [ ] 권한 철회 후 재실행·재허용 시 정상 복구 확인.

## iOS 실제 기기 및 Simulator

- [ ] Simulator: 루틴/SQLite/기본 권한 상태/전경 알림/라우팅 확인.
- [ ] 실기기: 허용/거부/provisional, 잠금 화면, 소리, 집중 모드, 백그라운드 전달 확인.
- [ ] 60개 이상 후보에서 가장 가까운 60개만 예약되고 앱 재개 후 보충되는지 확인.
- [ ] 알림 수정/취소, 앱 업데이트·기기 재시작·시간대 변경 후 복구 확인.
- [ ] 앱 제거 시 데이터가 삭제됨을 확인. 업데이트에서는 유지됨을 확인.
