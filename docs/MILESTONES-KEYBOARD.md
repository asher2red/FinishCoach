# 마일스톤 일괄 편집 및 모바일 키보드 대응

## 변경 사항과 파일

- `src/screens/Coach.tsx`: 기존 프로젝트 편집 상태를 재사용한다. ‘＋ 마일스톤 추가’는 고유 ID를 가진 초안을 즉시 목록 끝에 추가하고 새 입력창에 포커스를 준다. 기존 이름·순서 변경과 삭제도 초안에만 반영한다. 닫으면 폐기하고 재진입 시 저장된 값으로 구성한다. 저장 중 버튼 비활성화와 즉시 잠금(ref)으로 중복 저장을 막는다.
- `src/domain/projects.ts`: `saveProjectWithMilestones`가 모든 초안의 이름·ID·소속을 먼저 검증한 뒤 프로젝트와 마일스톤을 함께 변경한다. 기존 완료 시각은 보존하며 삭제는 기존 deletedAt 방식이다. 다른 프로젝트 데이터는 유지한다.
- `src/ui/design.tsx`, `InputVisibility.ts`: 공통 Field에 새 항목 자동 포커스, 여러 줄 입력 및 포커스 입력창 전달을 추가했다. 설명·완료 기준·메모에는 여러 줄 입력을 적용한다. 입력창 key나 선택 범위를 변경하지 않는다.
- `src/ui/EditorScroll.tsx`: 공통 네이티브 편집 스크롤. iOS KeyboardAvoidingView가 키보드에 맞춰 영역을 줄인다. 키보드 표시·프레임 변경, 포커스, 레이아웃·콘텐츠 크기 변경 때 입력창과 실제 스크롤 영역을 measureInWindow로 측정해 필요한 만큼만 스크롤한다. 키보드 높이 상수는 사용하지 않는다. 수동 스크롤·드래그 닫기를 지원한다.
- `src/ui/EditorScroll.web.tsx`: 웹의 Visual Viewport resize/scroll과 포커스를 구독한다. 화면이 줄어든 동안만 편집 영역의 최대 높이를 실제 보이는 높이에 맞추고 포커스 입력창을 가까운 위치로 스크롤한다. 복원 시 높이 제한을 해제한다. 데스크톱의 기존 크기는 유지한다.
- `app.json`: Android softwareKeyboardLayoutMode를 resize로 명시했다. 생성된 네이티브 소스는 직접 수정하지 않았다.
- `tests/projects.test.ts`, `e2e/milestones.spec.ts`, `e2e/coach.spec.ts`, `e2e/native/NavigationUITests.swift`: 일괄 편집·오류 복구·키보드 가시성 검증 및 기존 UI 흐름 갱신.

## 저장 방식

항목 추가 중에는 저장소를 호출하지 않는다. ‘프로젝트 저장’ 한 번에 기존 store.mutate가 최신 상태를 복제하고 도메인 검증을 수행한 뒤 기존 Repository.commit을 한 번 호출한다. IndexedDB/SQLite의 기존 트랜잭션이 프로젝트와 마일스톤을 원자적으로 저장한다. 성공한 경우에만 편집 창을 닫는다. 실패하면 기존 오류 영역에 원인을 표시하고 모든 초안을 남겨 재시도할 수 있다. 빈 항목은 ‘마일스톤 N 이름을 입력하세요’로 안내하며 이름을 입력하거나 해당 항목을 삭제해야 저장된다.

## 검증 결과

- TypeScript, lint 및 diff 공백 검사: 통과.
- Vitest 36개: 통과. 일괄 추가·수정·정렬·삭제, 완료 상태·다른 프로젝트 보존, 검증 오류 시 상태 불변 포함.
- 최종 웹 전체 테스트 10개: 통과. 세 개 항목 저장·재로딩, 강제 저장 오류 후 입력 보존과 재시도, 수정·추가·정렬·삭제·빈 항목 검증·취소 포함.
- 추가 Visual Viewport 테스트: 통과. 표시 높이 축소 시 입력창 가시성, 입력값·선택 범위 보존과 높이 복원을 실제 브라우저에서 검증한다. 이는 실제 모바일 키보드 테스트를 대체하지 않는다.
- Web export 및 Android/iOS JS 번들 export: 성공.
- iOS 27.1 시뮬레이터 Release 빌드·설치 및 XCTest: 통과. 새 마일스톤 3개 연속 추가 후 각 입력창이 키보드 상단보다 위에 위치함을 실제 프레임 좌표로 검증했다. 여러 줄 입력·입력값 유지·닫기와 새 편집 화면 복원도 확인했다.

## 남은 확인

Android 실기기와 실제 모바일 Safari/Chrome의 키보드는 미검증이다. Android는 새 바이너리에서 resize 설정을 적용해야 하며 이전 APK는 이번 변경을 포함하지 않는다. 각 기기에서 화면 하단 입력창, 입력창 간 이동, 여러 줄 커서, 키보드 닫기·회전 및 시스템 내비게이션 방식별 확인이 필요하다. iOS 시뮬레이터의 다중 디스플레이 때문에 XCTest 이미지 캡처는 검게 기록돼 문서에서 제외했으며, 검증은 UI 요소 좌표와 입력값으로 수행했다.
